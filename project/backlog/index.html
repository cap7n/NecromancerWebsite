    Follow-ups M0 surfaced¶

    • NEEDS FIX Flow-field rebuild is ~28 ms: a 2-frame hitch on every rally-point move. Run it on a worker thread (it's a pure function writing to its own arrays). Before M2.
    • TODO Re-run the benchmark on a mid-range CPU. Measured on an i9-13900K; the pillar target is mid-range, where single-threaded 800 could be 9-12 ms. PASS is provisional until then.
    • TODO Q14: judge crowd perception from the third-person camera (C, presets 1..6). If 300 already reads as a horde, 800 is budget to spend elsewhere. Do this before optimising for more agents.
    • IDEA Melee-lock: engaged agents skip separation entirely (Total War's paired-duel trick). Would make dense combat cheaper than open-field movement, inverting the cost curve. Highest-value optimisation known; measurable only once M2 has fighting.
    • IDEA Optimisation ladder for >800: temporal LOD (time-slicing) → distance sim-LOD → symmetric pairs → ghost tier → GDExtension. See Performance.
    • IDEA Scattered slots: clump origin + jittered slot offsets + a decaying deviation term, à la Total War's undead. The known route to thousands: near-free when calm, and it collapses netcode bandwidth to per-clump rather than per-agent. Costs some emergent local behaviour. Decide only after Q14 and after melee-lock is measured. See Performance.
    • NEEDS CARE Any distance-based sim LOD must key off nearest-of-all-players, not the local camera: split authority means my cheapened units are in your view.
    • TODO Chokepoint overlap is now visible and measurable. Tune separation strength for looks, not just cost.

    M1: The corpse field¶

    Design first. Unit System Design specifies capabilities and the derived pipeline: review and ratify it before writing code.

    • NEEDS DECISION Ratify or rewrite Unit System Design.
    • TODO Rewrite agent_sim.gd around the behaviour-byte pipeline (FLOCK / SLOT / ENGAGED). Keep the movement maths, keep spatial_hash.gd and flow_field.gd as-is.

    • MEASURE FIRST Target acquisition, time-sliced from day one. Same order of cost as separation; measure before tuning anything else.

    • TODO Corpse-field data structure: spatial hash + second MultiMesh + decay timer.

    • TODO Death pipeline: canned tip-over → corpse record, agent slot freed and reused. No ragdoll.
    • TODO 3-4 hand-authored death clips, random pick + random rotation.
    • TODO Feed verb: radius query against the hash → raise. Make it feel great; this is the signature input.
    • TODO Corpse quality carried from the source unit (a knight raises better than a peasant).
    • TODO Vertex-animation-texture bake pipeline. The one piece of tech that has to be right.
    • TODO Flat test arena + a spawner for target dummies.

    M3: Two players, one battle¶

    Reference implementation for most of this exists in OTR: see OTR Carry-Over.

    • TODO Port NetworkTickManager (distributed ownership, dirty flags, keepalive, MTU chunking) for the few entities: necromancers, elites, parties.
    • TODO Port StateBuffer (Hermite interpolation, snap distance) for those same entities.
    • TODO Horde replication à la horde_manager: packed XZ arrays, low Hz, client-side Y reconstruction, extended to per-player ownership.
    • TODO Steam lobby flow (GodotSteam, friends-only, overlay join): lift from OTR steam_manager + lobby UI.

    • TODO Ownership split: each machine sims its own 200 + half the enemy force.
    • TODO Quantised state packing (~8 bytes/unit) + remote interpolation over ~2 intervals.
    • TODO Reliable channel for deaths / raises / casts; unreliable for positions.

    • TODO Late join into a running battle + enemy-ownership handoff.
    • TODO Bandwidth + fps measurement harness (expect ~16 KB/s each way).
